# 職涯轉職規劃 app

單一 HTML + Firebase Realtime Database 即時同步 + PWA，用來管理轉職過程中的職缺追蹤、履歷、學習進度、時程安排與面試準備。

## 功能
- **儀表板**：追蹤中職缺數、學習中項目數、本月安排事項、面試紀錄數；近期時程與學習進度總覽。
- **職缺追蹤**：貼職缺網址、地點、工作性質、必要能力／加分能力、狀態（觀察中／已投遞／面試中／已錄取／已婉拒，卡片上可直接下拉切換），可篩選；依「類別」自動分區顯示，每個類別標籤會依名稱固定配色，方便一眼分辨。每筆職缺可用 1~5 顆星直接在卡片上點選「心儀程度」。薪資（可選擇月薪或年薪、下限／上限、備註，皆選填）只在有填寫時才會以小標籤顯示在地點旁，沒填或面議則不顯示，避免版面雜亂。收合狀態下就會顯示公司名、心儀星星、地點，職缺連結也改成小圖示按鈕，不用展開就能直接點開；新增／編輯職缺時，常用欄位（名稱、公司、地點、工作性質、狀態、類別、心儀程度、網址）在最上面，履歷版本、薪資、工作內容、能力、備註等收進可展開的「進階設定」，減少一次要填的欄位數量。編輯視窗不會因為點擊外部背景而關閉，需按「取消」或右上角關閉鈕。
- **我的履歷**：支援多個履歷版本（例如針對不同職缺類別準備不同版本），基本資料與求職目標（含地址）、自我介紹、工作經歷（可新增多筆）、學歷、專長與技能（列點顯示）、推薦人（姓名／職稱／公司／電話／Email）；工作內容、自我介紹、備註等欄位會自動判斷格式，若你打了列點符號（如 -、•、1. 等）就會顯示成項目清單，否則維持一般段落顯示。可從既有 PDF 履歷嘗試自動匯入內容（實驗性，需人工校對），也可將目前版本匯出成 PDF、Word（.docx）或 PowerPoint（.pptx）三種格式。職缺可選填「建議使用履歷版本」。
- **學習進度**：依「學習中／待學習／已學會」分組，可設定分類、目標日期、學習資源網址、備註；進度條可直接拖曳調整完成度，超過 0% 自動標記為學習中、達 100% 自動標記為已學會；可累加多筆「學習紀錄」（日期＋簡述）。
- **時程規劃**：月曆檢視，可安排學習、投遞履歷、面試、其他事項，點日期可查看/新增當天事項。
- **面試紀錄**：公司、職務、輪次、日期、結果，準備項目清單（可勾選，進度條顯示完成度）、面試筆記。
- **設定**：同步狀態燈號（綠/黃/紅）與最近同步時間、資料筆數、JSON 匯出／匯入備份、Firebase 設定顯示、登出。
- **密碼保護**：有設定 Firebase 時，開啟 app 會先要求 Email／密碼登入，才能讀寫雲端資料。

## 設定 Firebase（必要，否則僅能在單一裝置本機儲存）
打開 `index.html`，找到最上方的 `firebaseConfig`，換成你自己 Firebase 專案的設定值（Firebase 主控台 → 專案設定 → 一般 → 你的應用程式）。

若未設定 Firebase（欄位仍是 `YOUR_...` 佔位符），app 會自動退回使用瀏覽器 localStorage 本機儲存（僅該裝置該瀏覽器可見，不會跨裝置同步，也不會顯示登入畫面）。

### 1. 建立資料庫
Firebase 主控台 → Realtime Database → 建立資料庫（選一個離你近的地區，例如 asia-southeast1）。

### 2. 啟用登入方式（密碼保護）
1. Firebase 主控台 → Authentication → Sign-in method，啟用「電子郵件/密碼」。
2. 切到 Users 分頁 → Add user，建立你自己要用來登入這個 app 的 Email／密碼（這組帳密只有你知道，等於這個 app 的登入密碼）。

### 3. 設定資料庫安全規則
Realtime Database → Rules 分頁，貼上：
```json
{
  "rules": {
    "careerApp": {
      ".read": "auth != null",
      ".write": "auth != null"
    }
  }
}
```
發布（Publish）。這樣只有登入成功的使用者（也就是你自己）才能讀寫資料，其他人就算知道網址也進不去。

設定完成後重新整理 app，會先看到登入畫面，輸入你在步驟 2 建立的 Email／密碼即可。瀏覽器會記住登入狀態，之後不用每次都重新登入；設定頁可隨時按「登出」。

## 部署到 GitHub Pages
1. 建立一個新的 GitHub repository（可設為 public 或 private，Pages 免費版皆可用 public）。
2. 把本資料夾的 `index.html`、`manifest.json`、`service-worker.js` 一起上傳到 repo 根目錄（同一層）。
3. 進入 repo 的 Settings → Pages，Source 選擇 `main` 分支 / root，儲存。
4. 幾分鐘後即可用 GitHub 提供的網址（例如 `https://你的帳號.github.io/repo名稱/`）打開 app。
5. 手機瀏覽器打開該網址後，可選擇「加入主畫面」，即可像 App 一樣使用（PWA）。

## 資料備份
設定頁可隨時「匯出備份」下載 JSON 檔，或「匯入備份」還原資料（匯入會覆蓋目前所有資料，請先確認）。建議定期匯出備份存檔。

## 履歷版本與匯出
- 「我的履歷」頁最上方可切換／新增／重新命名／刪除履歷版本，方便針對不同職缺類別（例如數據分析 vs. 稽核）各自準備一份履歷內容。
- 「PDF 匯入（實驗性）」會用 pdf.js 讀取 PDF 文字，再用關鍵字（工作經歷、技能、自我介紹等）啟發式拆解成欄位，排版複雜或欄位命名不同的履歷可能拆不準，匯入前會先跳出預覽視窗讓你逐項確認、刪除或修改，確認後才會真的寫入。
- 「匯出履歷」按鈕可選擇三種格式：
  - **PDF**：開新分頁排版好履歷內容，自動叫出瀏覽器列印視窗，把列印目的地選成「另存為 PDF」即可存檔。
  - **Word（.docx）**：直接下載排版好的 Word 檔，可再自行編輯調整。
  - **PowerPoint（.pptx）**：以每個區塊一張投影片的方式下載簡報檔。
- 工作內容、自我介紹、學歷備註等欄位，會依你輸入時是否使用列點符號（-、•、1. 等）自動判斷要顯示成項目清單或一般段落，三種匯出格式都會套用同樣的判斷結果。
